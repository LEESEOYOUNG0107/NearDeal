# NearDeal 개발 기록 (설명용 노트)

나중에 프로젝트를 설명해야 할 때(발표, 면접, 포트폴리오 질문) 꺼내 보는 문서입니다.
`PORTFOLIO.md` 는 "무엇을 만들었나"를 짧게 보여 주는 소개서이고, 이 문서는 **"어떻게, 왜 그렇게 만들었고 어떤 문제를 어떻게 풀었나"** 를 말로 설명할 수 있게 정리한 것입니다.

---

## 1. 30초 소개 (먼저 이것만 외워 두기)

> NearDeal 은 당근마켓을 모델로 한 동네 중고거래 서비스입니다. Spring Boot 와 Oracle 로 만들었고,
> 회원가입과 JWT 로그인, 동네 설정, 상품 등록과 조건 검색, 찜, WebSocket 실시간 채팅, 거래 상태 변경, 알림을 구현했습니다.
> 상품 설명은 Gemini 로 초안을 만들어 주는 AI 기능도 있습니다.
> 기능 하나씩 만들고 그때마다 테스트하는 방식으로 21단계를 진행했고, 마지막에는 가입부터 거래 완료까지 전체 흐름을 자동으로 점검하는 스크립트와 단위 테스트 47개로 확인했습니다.

핵심 숫자: 서버 파일 81개 · 테스트 47개 · REST API 26개 · 화면 15개 · 통합 점검 60개 통과.

## 2. 개발 순서와 단계별로 한 일

| 단계 | 한 일 | 이 단계에서 기억할 점 |
|---|---|---|
| 1~3 | 상품 엔티티, 등록, 목록, 상세 | 판매자는 처음에 테스트용 번호(`userId`)로 받다가 나중에 JWT 로 교체하기 쉽게 만듦 |
| 4 | 수정/삭제 | 본인 상품만 가능(403) |
| 5 | 검색 | JPA `Specification` 으로 조건을 있는 것만 이어 붙임 |
| 6 | AI 상품 설명 | 처음 Anthropic → 무료로 쓸 수 있는 Gemini 로 변경 |
| 7~8 | 찜, 거래 상태 | 찜은 (회원, 상품) 유니크 |
| 9~10 | 채팅(REST) → WebSocket | REST 는 이력/목록, WebSocket 은 실시간 전달 |
| 11 | 알림 | 찜/새 메시지/상태 변경 3종, 중복 방지 규칙 |
| 12~13 | 회원가입, 로그인+JWT | BCrypt, 토큰 발급 |
| 14 | Spring Security + JWT | 모든 `/api/**` 기본 잠금, 공개 API 만 명시적으로 열기 |
| 17 | 동네 설정 | 내 동네 최대 2개, 첫 번째가 현재 동네 |
| 18 | 실제 사용자 연결 | 테스트 번호로 만든 옛 데이터를 실제 회원으로 이전 |
| 19 | Swagger | springdoc, 자물쇠/Authorize |
| 20 | 예외 처리, 검증, 보안 점검 | 공통 에러 형식, 스택트레이스 노출 차단 |
| 21 | 통합 테스트, 문서 | 전체 흐름 자동 점검 스크립트 |

개발 방식: "구조를 먼저 설명 → 한 기능만 구현 → 바로 테스트 → 내가 다음 단계라고 말하면 진행". 화면(Thymeleaf)은 내가 직접 만들고, 서버 코드를 그 화면에 맞춰 연결했다.

## 3. 설계 결정과 이유 (왜 그렇게 했나)

면접에서 "왜 ~로 했어요?" 라고 물으면 여기서 답을 꺼냅니다.

| 결정 | 이유 | 대안과 한계 |
|---|---|---|
| 테이블 이름 `member` (`user` 아님) | Oracle 에서 `USER` 는 예약어라 테이블 이름으로 못 씀 | |
| React 대신 Thymeleaf, 8080 포트 하나로 | 서버 하나로 바로 화면이 나오게 하려고 | 나중에 SPA 로 바꾸면 쿠키 JWT 와 헤더 JWT 두 경로가 하나로 정리됨 |
| JWT, 세션 없음(stateless) | 서버가 로그인 상태를 저장하지 않아도 되고 API/WebSocket 에서 같은 토큰을 씀 | 토큰을 중간에 무효화하기 어려움(로그아웃은 토큰 만료까지 유효) |
| JWT 에는 회원 번호와 만료 시각만 | payload 는 누구나 디코딩해서 읽을 수 있음 → 민감 정보 금지 | |
| `@CurrentUserId` 직접 만듦 | 컨트롤러가 `Long userId` 하나만 받으면 되게 | |
| 비밀번호 BCrypt | 되돌릴 수 없는 해시 + 솔트 자동 | BCrypt 는 72바이트 이후를 무시 → 한글(3바이트) 기준으로 길이 검사 |
| 모든 `/api/**` 기본 잠금 | 새 API 를 만들어도 실수로 공개되지 않음 | |
| REST + WebSocket 역할 분리 | 이력/목록은 요청-응답이 자연스럽고, 실시간은 푸시가 필요 | |
| 커밋 **후에** 방송 (`@TransactionalEventListener`) | 저장이 롤백됐는데 상대에게 메시지가 먼저 보이는 문제 방지 | |
| 알림에 `actorId` 저장 | "누가 했는지"로 중복 알림 방지 | 알림과 상품 사이에 외래키가 없어 상품 삭제 후에도 알림이 남음 |
| 동네를 `member.neighborhoods` 문자열 한 칸("a,b") | 최대 2개라 테이블을 따로 만들 필요가 작았음 | "같은 동네 이웃" 기능을 만들 거면 테이블 분리 필요 |
| 동네 매칭은 `지역 LIKE %동네%` | 행정구역 데이터가 프로젝트에 없어서 가짜 데이터를 만들지 않음 | 구→동 포함 관계는 못 잡음 |
| AI 는 `ChatClient` 인터페이스만 사용 | 공급자를 바꿔도 서비스/컨트롤러는 그대로 (실제로 Anthropic→Gemini 로 바꿈) | |
| AI 서비스는 상품 저장 코드에 의존하지 않음 | "AI 가 자동 등록하지 않는다"를 구조로 보장 | |
| 비밀값은 `.env` 와 환경변수만 | 코드와 Git 에 키가 남지 않게 | `.gitignore` 에 `.env` 포함 |
| 에러 응답을 한 형식으로 통일 | 프론트가 한 가지만 처리하면 됨, 내부 정보 노출 방지 | |

## 4. 문제 해결 기록 (증상 → 원인 → 해결 → 배운 점)

설명할 때는 **"무슨 증상이었고, 어떻게 원인을 좁혔고, 무엇을 바꿨나"** 순서로 말하면 됩니다.

### 4-1. 서버/환경
| 증상 | 원인 | 해결 | 배운 점 |
|---|---|---|---|
| `localhost:8080` 접속 시 Whitelabel 404 | `/` 에 매핑된 화면이 없었음 | 홈 화면 추가(Thymeleaf) | 404 가 "서버 고장"이 아닐 수 있다 |
| 서버 시작 실패, 포트 8080 사용 중 | 이전에 띄운 서버가 남아 있었음 | 남은 프로세스 종료 후 재시작 | 테스트로 띄운 서버는 반드시 종료 확인 |
| `ORA-04043`, 테이블 없음 | 설정을 덮어쓰면서 `ddl-auto=update` 가 빠짐 | 속성 복구 | 설정 파일이 바뀌면 기능이 조용히 깨진다 |
| `ORA-00904`, `ORA-01758` (채팅) | DB 에 이미 있던 `chat_room`/`chat_message` 테이블의 컬럼 이름이 내 엔티티와 달랐음 | DB 는 그대로 두고 엔티티를 기존 컬럼에 맞춤 | 기존 데이터는 함부로 바꾸지 않는다 |
| 빌드가 20분 | 테스트 때 띄운 서버 프로세스가 남아 CPU 점유 | 내가 띄운 프로세스 종료 | 남은 프로세스 확인 습관 |
| 코드를 고치면 로그인이 풀림 | DevTools 가 서버를 재시작하고, `JWT_SECRET` 이 없으면 무작위 키를 새로 만들어 기존 토큰이 전부 무효 | `.env` 에 `JWT_SECRET` 추가 | 임시 키는 개발 편의, 운영은 고정 키 |
| 컴파일 오류 | 내가 만든 화면 컨트롤러가 호출하는 `ChatService` 메서드가 아직 없었음 | 화면 계약에 맞춰 메서드 구현 | 화면과 서비스의 계약을 먼저 맞춘다 |

### 4-2. AI(Gemini)
| 증상 | 원인 | 해결 |
|---|---|---|
| AI 설명이 안 됨 (여러 번 반복) | **원인이 여러 겹이었음**: ① 모델 이름이 틀려 404 → ② 키가 비어 있으면 앱이 시작되지 않음 → ③ Google 프로젝트에서 403(권한) → ④ IDE 실행 설정의 환경변수가 `.env` 의 새 키를 덮어씀 | 하나씩 분리해서 확인: 올바른 모델 이름, 더미 기본값(`no-key-set`), 새 키 발급, IDE 환경변수 제거 |
| AI 요청이 5분 넘게 응답 없음 | Gemini 가 과부하(503)일 때 SDK 가 오래 재시도 | 25초 상한을 두고 초과하면 **502** 로 끝냄 |
| 클라이언트에 AI 오류 원인이 그대로 노출 | 예외 메시지를 응답에 실었음 | 일반 문구만 응답, 원인은 서버 로그에만 |

**배운 점**: 같은 증상("안 된다")도 원인이 여러 개일 수 있어서, 로그의 **가장 안쪽 원인(root cause)** 을 보고 하나씩 지워 나가야 한다. 키 값은 채팅이나 코드에 쓰지 않고 길이와 앞 4글자 형식만 확인했다.

### 4-3. 기능 버그
| 증상 | 원인 | 해결 |
|---|---|---|
| 찜을 껐다 켜면 판매자에게 알림이 계속 쌓임 | 토글할 때마다 알림 생성 | `actorId` 저장 + "같은 사람이 이미 보낸 알림이면 만들지 않음" |
| 상품 가격이 입력과 다르게 나온다, 사진이 안 올라간다 | 서버 값은 정상(19979 → 19,979원 확인). 실제로는 숫자 입력칸에서 마우스 휠로 값이 바뀌고, 사진이 조용히 제외되고, 버튼을 두 번 눌러 이중 제출 | 숫자 전용 텍스트 입력, 제외된 사진 안내 문구, 제출 중 버튼 잠금 |
| 한 상품에 채팅방/찜을 빠르게 두 번 누르면 500 | 동시에 같은 행을 만들려다 DB 유니크 제약에 걸림 | DB 제약이 데이터는 지켜 주고, `DataIntegrityViolation` 을 **409** 로 변환 |
| `?minPrice=abc` 가 500 | 쿼리 파라미터 바인딩 오류를 처리하는 곳이 없었음 | `BindException` 을 400 으로 변환 |
| 검색어 `%` 를 넣으면 전부 나옴 | `%`, `_` 가 LIKE 와일드카드로 동작 | 이스케이프해서 글자 그대로 검색 |
| 긴 제목을 넣으면 DB 오류(500) | 길이 제한이 없었음 | 화면 폼 제한(제목 100, 지역 50, 가격 10자리)에 맞춰 DTO 와 서비스에 검증 |

### 4-4. 보안 점검에서 찾은 것
| 발견 | 조치 |
|---|---|
| **실패 응답에 스택트레이스가 통째로 노출** (DevTools 기본값) | `spring.web.error.include-stacktrace=never`. **Spring Boot 4 에서 속성 이름이 `server.error.*` → `spring.web.error.*` 로 바뀌어서** 처음 설정은 효과가 없었음. 실제로 응답을 확인해서 발견 |
| 로그인 응답 시간으로 가입 여부를 추측 가능 | 없는 이메일도 더미 해시와 비교 |
| 72바이트 넘는 비밀번호 | 가입/로그인 모두 바이트 길이 검사 |
| 화면 폼 경로가 REST 검증을 우회 | 서비스 계층 `@Validated` 로 같은 규칙 적용 |
| 로그인 횟수 제한 없음 | **고치지 않음**(알려진 한계로 기록) |

|---|---|

## 5. 나중에 설명할 때 "내 말로" 할 수 있어야 하는 개념

이 프로젝트는 AI 도구와 함께 단계별로 만들었습니다. 면접에서는 **"무엇이 어떻게 동작하는지"** 를 직접 설명할 수 있어야 하니, 아래는 한 번씩 소리 내어 말해 보세요.

1. **JWT 로그인 흐름**: 로그인 → 서버가 서명한 토큰 발급 → 이후 요청마다 `Authorization: Bearer` → 필터가 서명/만료 검사 → `@CurrentUserId` 로 컨트롤러에 회원 번호 전달.
2. **왜 비밀번호를 해시로 저장하나**: DB 가 유출돼도 원문을 알 수 없게. BCrypt 는 솔트를 자동으로 붙이고 일부러 느리다.
3. **REST 와 WebSocket 의 차이**: 요청-응답 vs 연결 유지 푸시. 이 프로젝트에서는 이력은 REST, 실시간은 STOMP.
4. **STOMP 구독 검사**: 연결할 때 토큰을 확인하고, 방을 구독할 때 "참여자인가"를 확인.
5. **왜 커밋 후에 방송하나**: 롤백될 데이터를 상대에게 보여 주지 않기 위해.
6. **JPA Specification**: 조건이 있는 것만 AND 로 이어 붙여 하나의 쿼리를 만든다. 값은 파라미터 바인딩이라 SQL 주입이 안 된다.
7. **영속성 컨텍스트와 더티 체킹**: 상품 수정이 `save` 없이 반영되는 이유(트랜잭션 안에서 엔티티를 바꾸면 커밋 때 UPDATE).
8. **DB 제약 vs 코드 검사**: 중복 찜은 코드로 한 번 막고, 동시 요청은 DB 유니크 제약이 최종 방어.
9. **공통 예외 처리(`@RestControllerAdvice`)**: 예외를 한 곳에서 같은 JSON 으로 바꾸고 내부 정보는 숨긴다.
10. **환경변수와 `.env`**: 비밀값을 코드에 두지 않는 이유와 방법.

## 6. 예상 질문과 답변 틀

- **가장 어려웠던 점은?** → AI 설명이 안 되던 문제. 원인이 모델 이름, 빈 키, 프로젝트 권한, IDE 환경변수로 **네 겹**이어서 하나씩 지워 가며 찾았다. (4-2)
- **보안은 어떻게 신경 썼나?** → BCrypt, JWT 최소 정보, 기본 잠금, 참여자 검사, 스택트레이스 차단(직접 응답을 열어 보고 발견), 비밀값 `.env`. 못 한 것은 로그인 횟수 제한. (4-4)
- **동시성 문제는?** → 중복 찜/채팅방은 DB 유니크 제약으로 데이터를 지키고 409 로 응답. 조회수는 읽고-더하기라 동시에 많으면 일부 누락될 수 있어 알고 있는 한계.
- **테스트는 어떻게 했나?** → 단위 테스트 47개(서비스 규칙, JWT, 예외 처리기) + 실제 서버에 가입~거래 완료를 실행하는 점검 스크립트(WebSocket 포함).
- **다시 만든다면?** → 동네를 별도 테이블로, 알림과 상품 사이 외래키, 로그인 횟수 제한, 앱 전용 DB 계정, 화면을 SPA 로 분리해 인증 경로를 하나로.
- **AI 는 어떻게 안전하게 썼나?** → 입력하지 않은 정보는 지어내지 않게 시스템 프롬프트, 입력 안의 지시문은 따르지 않기, 자동 등록 금지(구조), 25초 상한, 오류 원인 비공개.

## 7. 기록해 둘 것 (잊어버리기 쉬운 정보)

**실행 방법**
```
.env 에 DB_PASSWORD, GEMINI_API_KEY, JWT_SECRET 설정
./gradlew.bat bootRun        → http://localhost:8080
Swagger UI                    → /swagger-ui.html
전체 점검                      → node docs/e2e-scenario.mjs
테스트                         → ./gradlew.bat test
```

**꼭 알아 둘 환경 사실**
- 환경변수가 `.env` 보다 우선한다(IDE 실행 설정의 환경변수가 `.env` 를 덮어쓴 적이 있다).
- DB: Oracle XE 21c, 접속 계정이 `SYSTEM`(운영 전 전용 계정으로 분리 필요).
- Spring Boot 4 는 이름이 바뀐 속성이 있다(`spring.web.error.*`). 인터넷 예제가 `server.error.*` 라고 해도 확인이 필요.
- DevTools 는 코드가 바뀌면 서버를 재시작한다. `JWT_SECRET` 없이는 그때마다 로그인이 풀린다.
- 원래 있던 `chat_room`/`chat_message` 테이블 구조에 엔티티를 맞춰 놓았다(이 테이블의 컬럼을 바꾸지 말 것).

**알려진 한계 (질문 받기 전에 먼저 말할 수 있게)**
- 로그인 횟수 제한 없음 · 동네 매칭은 단순 포함 · 알림은 푸시가 아님 · WebSocket 토큰은 접속 때만 검사 · 알림과 상품 사이 외래키 없음 · AI 호출 횟수 제한 없음 · 조회수 동시성 · 화면과 REST 의 인증 경로가 둘.
